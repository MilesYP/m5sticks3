# KICKOFF P2：電源鍵新機制＋省電（續航）

> 2026-11-21 Miles 與 Claude 討論定案（Cowork）。這一片只動電源鍵、螢幕開關、Wi-Fi 斷線時機、電量顯示與低電量關機。
> **A、B 鍵維持現狀；Scroll Unit 的配置等之後其他功能開發時再定**（G2 功能驗收也延後）。
> 開工條件：Miles 說「開始實作」。

## 0. 起因與目標

- 充飽拔線 21 分鐘掉到 67%（P1 之前推估平均約 230mA，電池 250mAh）。P1 之後沒有重新量。
- M5PM1 讀不到電流（M5Unified 對 PM1 沒有電流讀數）→ 一律用「同一情境、拔線、`h` 電壓紀錄每分鐘下降速度」比較。
- 目標：螢幕（推估最耗電）可以隨時手動關；放著不用時 Wi-Fi 會斷；電量用到見底前自動安全關機。

## 1. 電源鍵（M5PM1 管的那顆）

### 1-1. 兩種機制

| | 新機制（預設） | root（原廠） |
| :-- | :-- | :-- |
| 單按 | 開關螢幕（韌體判斷） | 開機／重置（PM1 硬體） |
| 連按兩下 | 無動作（硬體雙擊關機已關掉） | 關機（PM1 硬體） |
| 連按五下 | **強制關機**（韌體判斷；給「韌體還活著但畫面卡住」用） | — |
| 長按 | 按住時畫面顯示進度；**3～5 秒之間放開＝關機**；**按滿 5 秒再放開＝進 root** | 長按到綠燈閃＝下載模式（PM1 硬體） |
| 下載模式 | 鎖住（`DL_LOCK`） | 開放 |
| PM1 看門狗 | **開**（主迴圈餵狗；韌體卡死就自動重置） | 關 |

- **關機狀態下單按就開機**（板子限制：關機時 ESP32 沒電，只有 PM1 決定開不開機；Miles 選單按開機，不做「長按才開」的軟體補救）。插線會不會自動開機不特別處理。
- root：進入時把 PM1 的單按重置、雙擊關機、下載模式全部恢復原廠、看門狗關掉；畫面角落顯示「ROOT」。按一下（硬體重置）重新開機後回到新機制。
- **關機時正在說話、上傳或播放 → 直接中止**，不等它完成。急停（HID 模式 A 鍵、所有模式 B 按住 3 秒）維持最高優先，不經過電源鍵邏輯。

### 1-2. 查證過的 PM1 介面（官方 `m5stack/M5PM1` 的 `src/M5PM1.h`）

| 暫存器 | 內容 | 用途 |
| :-- | :-- | :-- |
| `0x48` BTN_STATUS | bit7 `BTN_FLAG`（讀了就清）、bit0 `BTN_STATE`（即時） | 韌體輪詢電源鍵 |
| `0x49` BTN_CFG_1 | bit7 `DL_LOCK`、bit6:5 雙擊間隔、bit4:3 長按時間、bit2:1 單擊時間、bit0 `SINGLE_RST_DIS` | 關單按重置、鎖下載模式 |
| `0x4A` BTN_CFG_2 | bit0 `DOUBLE_OFF_DIS` | 關雙擊關機 |
| `0x0A` WDT_CNT | 0＝關、1～255＝秒 | 看門狗逾時 |
| `0x0B` WDT_KEY | 寫 `0xA5`＝餵狗 | 主迴圈餵 |

- 一律用 `M5.In_I2C.readRegister8／writeRegister8`（位址 `0x6E`）直接讀寫，不另加 M5PM1 函式庫。寫完讀回驗證。
- 關機用 M5Unified 的 `M5.Power.powerOff()`（`M5PM1_Class::powerOff`）。

### 1-3. 風險與規則（要寫進 CLAUDE.md）

1. **PM1 的設定會留著**：重置 ESP32 不會清，**換燒其他韌體（例如 Bruce）也會帶著**——單按不重置、雙擊不關機、看門狗一直倒數（別的韌體不會餵 → 每 N 秒被重置）。**燒其他韌體前一定先進 root**。開機時韌體一律重新寫一次新機制設定，不假設現值。
2. **看門狗和燒錄**：esptool 把 ESP32 拉進 ROM 燒錄時沒人餵狗。逾時暫定 **60 秒**（USB 燒錄約 20～40 秒），第一件事實測「燒錄中會不會被重置」；不行就加長或在燒錄前進 root。
3. **主迴圈最長卡多久**：目前最長約 0.6 秒（放開 A 的 `stopRecording`），60 秒逾時足夠；餵狗放主迴圈（不放 task），主迴圈卡死才會觸發。
4. 輪詢電源鍵在主迴圈、每 20ms 一次（內部 I2C 只有主迴圈在用）；長按計時以「按下時刻」算，主迴圈偶爾卡 0.6 秒不影響 3／5 秒判斷。PM1 自己的 I2C 閒置休眠不開。

## 2. 螢幕開關（所有模式）

- 單按電源鍵＝關螢幕：背光 0＋面板睡眠（`M5.Display.sleep()`），**停止畫圖**（主迴圈不畫、不送螢幕）；模式照常運作（HID、RF、空中滑鼠都繼續）。
- 單按再開：`M5.Display.wakeup()`，下一張整張送（`ui_fx::invalidate()`）。
- **Desktop 關螢幕時**：拍打、拿起、聲音都不叫醒；**短按 A 不理會；長按 A（≥0.6 秒）＝叫醒螢幕並連回中控，不開始錄音**（要說話放開再按一次）。待機收音（睡著聽聲音）關掉。
- 其他模式關螢幕時，A／B 照原功能（HID 急停、空中滑鼠左鍵等不受影響）。
- 急停發生時（Safe 紅底 KILLED）一律亮螢幕。

## 3. Wi-Fi 斷線（只在 Desktop）

- **睡著滿 3 分鐘**、或**手動關螢幕滿 3 分鐘** → 斷 Wi-Fi（不是省電模式，是真的斷）。
- 叫醒（拿起、拍、按 A、開螢幕）或按 A 說話 → 重連；按 A 說話時沿用 B3b-5「先錄著，連上再從頭送」。重連約 3～5 秒（含 TLS）。
- 斷線、重連一律走 `net_hub` 指令佇列，由網路 task 執行（鐵則七第 11 點）；家裡優先邏輯不動。
- 語音進行中、上傳沒送完不斷。
- **插著線＝永不睡眠、永不斷線**（11-22 Miles）：插線時桌寵不會進想睡／睡著、背光不調暗、Wi-Fi 不斷；**只有手動單按電源鍵關螢幕**才進睡眠，關螢幕滿 3 分鐘照樣斷 Wi-Fi。拔線後恢復一般規則（靜置計時從拔線那一刻重新算）。這取代 A4b「插著線背光最低停在想睡那一級」。
- 資訊頁的雲端資料斷線期間保留舊值並標時間（A5-2 既有行為），重連後中控會補送。

## 4. 電量顯示與低電量關機

- 實際電量（M5PM1 讀數平滑後）≤3% 時強制關機；**畫面顯示＝(實際 − 3) ÷ 97 × 100**，所以畫面看到 0% 才關。
- 低電量閃爍門檻（<20%、<5%）、資訊頁、狀態列、Friday 回報的電量全部用畫面數字。序列埠 `c<n>` 假裝的也是畫面數字。
- 觸發條件：**沒插線＋連續 30 秒實際電量 ≤3%**（說話、播放時電壓會瞬間掉，避免誤關）。關機前畫面顯示「電量不足」約 2 秒。

## 6. 驗收清單

1. 單按電源鍵：螢幕關／開，模式不中斷（Desktop、資訊頁、其他模式各試一次）。
2. 快速按兩下：螢幕關了又開，**不會關機**。
3. 連按五下：強制關機。
4. 按住 3～5 秒放開：關機；關機後單按開機。
5. 按滿 5 秒放開：畫面顯示 ROOT；單按＝重置後回新機制；在 root 雙擊＝關機。
6. 說話、上傳、播放中按住 3 秒放開：直接關機。
7. HID 模式 A 急停、任一模式 B 按住 3 秒急停照常最高優先；急停時螢幕亮。
8. 看門狗：序列埠指令讓主迴圈卡死 → 約 60 秒自動重置；正常使用（含長回放）不被誤重置；燒錄成功。
9. Desktop 關螢幕：拍、拿起、拍手都不亮；短按 A 不理；長按 A 亮螢幕＋連回中控、不錄音。
10. 睡著 3 分鐘、關螢幕 3 分鐘 → 序列埠印 Wi-Fi 斷線；資訊頁 LINK 顯示斷線。插著線：放著不會想睡／睡著、背光不暗、不斷線；插線時手動關螢幕 3 分鐘照樣斷。
10b. 問 Friday「怎麼進 root」「怎麼關機」「怎麼關螢幕」答得對。
11. 斷線後拿起／按 A → 重連；直接按 A 說話 → 先錄、連上後 Friday 正常回答。
12. 語音中、上傳中不會因計時斷線。
13. `c3`（畫面 3%）等假裝數字下，閃爍門檻正確；資訊頁、狀態列、Friday 回報一致。
14. 低電量關機：用序列埠假裝「實際 ≤3%」連續 30 秒 → 顯示「電量不足」後關機；插線時不觸發。
